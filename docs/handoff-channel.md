# 分支投递通道说明(写给任务投递方/复核方)

这个分支上的 `task-*.md` 系列文件是任务交接信道。**文件名的后缀表示「现在轮到谁」**,规则如下:

| 文件名 | 含义 | 谁的回合 |
|---|---|---|
| `task-x.md` | 待办任务书(新投递 / 复核退回重做 / 异议裁决后重排) | **执行方** |
| `task-x.review.md` | 执行方已实施完毕,等复核 | **你** |
| `task-x.discuss.md` | 执行方有异议待裁决(见 md 末尾「## 异议」段,内含待拍板选项) | **你** |

**你回信的动作永远只有一个**:把文件改回 `task-x.md`(去掉状态后缀、保留原词干),在内容里写清你的要求或裁决,**然后 push**——不推送执行方看不到(执行方靠分支 SHA 前进发现变化)。

- 复核 `.review.md` 有问题 → 改回 `task-x.md` + 在文末追加复核意见 + push(执行方会重读全文再改)
- 裁决 `.discuss.md` → 改回 `task-x.md` + 写明选了哪个选项(或维持原案)+ push
- 复核通过 → 到 GitHub 合并对应 PR 即可,任务书保持 `.review.md` 不动

代码交付一律走 PR(执行方只开不合),main 永远由你合并。
